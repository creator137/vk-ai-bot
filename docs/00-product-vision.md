# Product Vision

## Project

VK AI Platform

## Goal

Создать MVP AI-сервиса внутри VK, где пользователь может отправлять текст и изображения, получать ответы от нескольких AI-провайдеров, а также оплачивать доступ через подписку или пакет кредитов.

## MVP scope

В первую версию входят:

- интеграция с VK как основным пользовательским каналом
- обработка текстовых запросов
- обработка запросов с изображением
- интеграция с несколькими AI-провайдерами
- профиль пользователя на основе VK user id
- учет доступа через:
  - подписку
  - пакет кредитов
- интеграция платежей через YooKassa и Robokassa
- базовая история запросов
- базовая серверная логика лимитов, списаний и выдачи доступа
- базовые фоновые задачи для тяжелых операций
- базовые логи и контроль критичных сценариев

## Non-goals for MVP

В первую версию не входят:

- сложная админка
- полноценный web-кабинет
- микросервисная архитектура
- сложная аналитика
- реферальная система
- промокоды
- партнерская программа
- сложная memory system как у полноценных AI чатов
- автопродление со сложной бизнес-логикой
- многоуровневая ролевая модель
- сложный антифрод
- избыточное покрытие тестами ради процента покрытия

## Core product principles

- MVP должен быть небольшим, но production-oriented
- Архитектура должна позволять спокойно развивать проект дальше
- Нельзя завязывать систему на одного AI-провайдера
- Нельзя смешивать transport, billing и AI-логику
- Нельзя делать бизнес-критичные части “на коленке”
- Нужно минимизировать хаос для дальнейшей разработки двумя разработчиками и AI-инструментами

## Users

Основной пользователь:

- пользователь VK, который взаимодействует с сервисом через сообщения/интерфейс VK

Дополнительные участники:

- администратор/разработчик проекта
- поддержка проекта на серверной стороне

## Monetization model

Поддерживаются две модели доступа:

- подписка на определенный период
- покупка пакета кредитов

Логика доступа:

- сначала система проверяет активную подписку
- затем доступные лимиты/кредиты
- если доступа нет — предлагает оплату

## Technical direction

Проект строится как модульный монолит на Python.

Основной стек:

- Python 3.12
- FastAPI
- PostgreSQL
- Redis
- Dramatiq
- Docker Compose

## Delivery principle

Проект реализуется небольшими шагами:

- анализ задачи
- план
- реализация малого законченного куска
- тесты на критичные сценарии
- маленький commit
- обновление project status
